Terasweep performance

Fit a model, rank a parameter plan, and see which work the sweep can share.

Terasweep fits Ridge, DLinear, LightGBM regression, and TiDE on prepared numeric matrices. Its parameter sweep evaluates an ordered list of model settings using mean absolute error on a labeled validation split.

Two runs

A single fit returns predictions in input order. A sweep ranks the settings and returns the winning predictions, validation MAE, and the number of distinct fits.

Tabular models accept multiple numeric features. DLinear and TiDE accept one observed series and predict the next value. Fit a candidate using training data, choose settings on validation data, and reserve a holdout for the chosen model.

Ridge training statistics

Fits at different regularization strengths reuse the statistics computed from fixed training data.

The calculation Ridge shares

With an intercept, Ridge centers the features and target before forming the Gram matrix (G = XᵀX) and the right-hand side (h = Xᵀy). Solving ((G + αI)w = h) gives the coefficients. The intercept is recovered from the training means.

The Gram matrix and right-hand side depend on the training data. A different α changes the diagonal and requires a new solve. Changing the intercept setting selects the raw or centered statistics.

Sweep dependencies

A duplicate training configuration can reuse its fit, predictions and validation score.

Count the distinct fits

An ordered plan can repeat settings. The sweep identifies equivalent training configurations, fits and scores the first occurrence, and gives exact score ties to the earliest entry. Its output records both the number of plan entries and the number of fits.

Repeat a model plan

Each distinct setting appears the same number of times in this example.

With 100 distinct settings, the sweep needs 100 fits. Ridge still shares input statistics and DLinear shares designs at the same lookback and kernel. LightGBM and TiDE reuse backend setup.

Reference parity

Compare the same prepared inputs and model settings with an independent upstream fit.

Match the inputs before comparing outputs

Freeze the training and validation matrices. Use the same model settings, causal windows for series models, and backend versions. Then check every prediction, the validation score, and the winning trial.

The live audit compares Ridge and DLinear numerically with Limen and checks LightGBM and TiDE bit for bit with their upstream models on the tested environment. All four cases also check the ten-decimal formatted predictions.

Check your understanding

Which comparison can establish that the sweep preserved the model calculation?

Pair up corresponding predictions and compare them on matched inputs. Also check the ranking when the claim concerns sweep results.

Read a measurement

Separate a trial count from the number of distinct fits, and compare runtimes on matched workloads.

Separate reuse from training speed

A sweep speedup can reflect shared training statistics, fewer fits, or shared backend startup. A single-fit comparison answers a different question. Record which phases each timer includes and keep model settings, evaluation, and requested trials matched.

When evaluating a runtime claim, check the train and validation shapes, unique fit count, hardware, and backend versions. Time measured at a smaller scale can support a projection, which should be identified separately from measured results.

The historical benchmark reports are retained in the research record with their original workloads and timing boundaries.

Run the checks

Start with the bundled examples and carry the exact data, settings and source into your own comparison.

Run the package examples

From the repository root, build the package, fit the concrete strength example, and run the ordered model plan.

make build
python3 scripts/model_run.py fit docs/examples/ridge.json
make run
make test

The example sweep has four entries and three distinct Ridge fits. Its JSON receipt returns the winning model's position in the plan and predictions in validation row order.

The optional reference audit also exercises LightGBM and TiDE. Follow the backend instructions to enable them.
